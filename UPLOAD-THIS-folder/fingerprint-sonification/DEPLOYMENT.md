# Deploying to Streamlit Community Cloud

Free, public, HTTPS, and it redeploys on every push. No Dockerfile, no server
management. This guide takes you from the local repo to a public URL.

---

## 0. Before you publish anything

The app accepts fingerprint images, which are biometric data. Publishing means
strangers can send their own prints to your host. A few decisions to make
deliberately:

- **The app does not store uploads.** Images are written to a temp file, processed,
  and deleted inside `src/web_jobs.py`. Keep it that way.
- **The built-in sample exists so nobody has to upload anything to try it.** Lead
  with that in whatever you post publicly.
- **You are the data controller for what passes through it.** Add your own
  contact/removal note if this is more than a demo.
- The repo no longer ships stock photography. `images/sample_fingerprint.png` is
  generated by `src/ml/synthetic.py`, so there is no third-party image licence.

---

## 1. Push the repo to GitHub

The project is already a git repo with commits. Create an **empty public** repo
on GitHub (no README, no .gitignore), then:

```bash
cd Classic-Fingerprint-Pipeline

git remote add origin https://github.com/<your-username>/fingerprint-sonification.git
git branch -M main
git push -u origin main
```

Check before pushing:

```bash
git status                       # should be clean
git ls-files | grep -E '\.wav$|\.pt$|venv|datasets/.*csv' || echo "no data or weights tracked"
```

`datasets/`, `checkpoints/`, `output/` and the venv are gitignored, so the push
stays small. The sample image and all source files are included.

> **Do not commit `checkpoints/ridge_segmentation.pt`.** The free tier gives you
> about 1 GB of RAM; PyTorch alone is ~800 MB and the app will be killed. See
> step 6 if you want ML segmentation in production.

---

## 2. Deploy

1. Go to **https://share.streamlit.io** and sign in with GitHub.
2. Authorise Streamlit to read your repositories (public repos only is enough).
3. Click **Create app** → **Deploy a public app from GitHub**.
4. Fill in:
   - **Repository:** `<your-username>/fingerprint-sonification`
   - **Branch:** `main`
   - **Main file path:** `app.py`
5. Open **Advanced settings**:
   - **Python version:** `3.11`
   - **Secrets:** leave empty (the app needs none)
6. Click **Deploy**.

First build takes 3–6 minutes (numpy/scipy/scikit-image need compiling or
downloading wheels). You get a URL like:

```
https://<your-app-name>.streamlit.app
```

---

## 3. Verify the deployment

1. The page should load with the uploader and the sidebar.
2. Tick **"No print handy? Use the built-in sample"**.
3. Set duration to 10 s and press **Generate sound**.
4. You should get an audio player, an analysis figure, and three download buttons.

If that works, the deployment is correct.

---

## 4. Things that will bite you (and the fixes)

**`ImportError: libGL.so.1`** — this is why `requirements.txt` pins
`opencv-python-headless` rather than `opencv-python`. The GUI build needs system
libraries the free tier does not have. Do not switch it back.

**App dies during "Generating"** — you are probably out of memory. The usual
cause is adding `torch`. Keep the web deployment CV-only.

**Uploads rejected** — the limit is 20 MB, set in `.streamlit/config.toml`
(`[server] maxUploadSize`) and enforced in `src/web_jobs.py` (`MAX_UPLOAD_BYTES`).
Raise both if you need to, but large photos are slow to process anyway.

**Long renders** — the duration slider goes to 60 s. A 60 s render at 320 px
takes a few seconds; that is fine. The free tier sleeps idle apps, and the first
visit after sleeping takes ~10–30 s to wake.

**It says "Generating" forever** — check the app's logs in the Streamlit Cloud
dashboard (⋮ → *View logs*). The traceback is there.

---

## 5. Updating the app

Streamlit Cloud watches the branch. Any push redeploys automatically:

```bash
git add -A
git commit -m "tweak the UI"
git push
```

You can also force a reboot from the dashboard if a container gets stuck.

---

## 6. If you want ML segmentation in production

The `ml` option only appears when **both** conditions hold:

- a checkpoint exists at `checkpoints/ridge_segmentation.pt` (or the path in the
  `RIDGE_CHECKPOINT` environment variable), and
- `import torch` succeeds.

To ship it you would need to:

1. Commit the checkpoint (4.4 MB) — e.g. `git add -f checkpoints/ridge_segmentation.pt`,
   or host it somewhere and download it on first run.
2. Add `torch` to the deployment's requirements.
3. Accept that a CPU torch install is slow to build and close to the memory
   ceiling. On the free tier, expect instability.

**Recommendation:** keep the public demo CV-only. The CV baseline is fast, needs
no weights, and is the honest baseline anyway. Run ML locally.

## 7. Alternatives, briefly

| Host | Fit | Notes |
| --- | --- | --- |
| **Streamlit Community Cloud** | Best | Free, zero config, redeploys on push. Sleeps when idle. |
| **Render** | Good | Free web service; needs a start command `streamlit run app.py --server.port $PORT --server.address 0.0.0.0`. Spins down after inactivity. |
| **Railway** | Fine | No permanent free tier any more; usage-based trial credit. Same start command. |
| **Hugging Face Spaces** | Good | Free, Streamlit SDK supported, decent RAM. Best alternative if you hit memory limits. |

For Render/Railway, add this start command in the dashboard:

```bash
streamlit run app.py --server.port $PORT --server.address 0.0.0.0 --server.headless true
```

## 8. Local pre-flight check

Run these before you push, so a broken deploy never happens:

```bash
python -m pytest -q          # includes three tests that execute the real app
streamlit run app.py         # click through the sample path once
```

The test suite runs `app.py` inside Streamlit's test harness, so an import error
or a removed widget argument fails locally instead of in the browser.
